## 2. 本轮改动实机验证项（6 项）

### (1) 项目多目录（多 root）保存/编辑与任务移入、跨项目移动

- **人测动作**：
  1. 在独立 Web 新建或编辑项目，通过服务端目录选择器添加 2 个目录并保存；再次打开编辑，切换主要目录、移除其中 1 个目录后保存。
  2. 将一条“不在项目中”的任务，或另一项目下的任务（其 `cwd` 不在目标项目目录列表内）移入目标项目，在弹出的确认框点击确认将文件夹加入项目。
- **期望结果**：
  - 项目可保存多个服务端目录，只剩最后 1 个目录时隐藏移除入口（不会产生 0 root 项目）。
  - 任务移入或跨项目移动时若原 `cwd` 不在目标项目目录中，先弹出确认提示；确认后将该任务已持久化的 `cwd` 追加为目标项目目录并更新项目归属，任务原 `cwd`、聊天历史与磁盘文件均保持不变。
- **风险与边界**：
  - 跨 Host 任务移动仍拒绝（`project.cross-host-move`）。
  - 普通远端（真实 Source Server / 桌面远控）仍维持单 root 且目录不可变限制。

### (2) 项目记忆 Markdown 页内预览、编辑保存与冲突保护

- **人测动作**：
  1. 进入“设置 -> 记忆”，点击任一服务端项目记忆文件，查看页内 Markdown 渲染并点击“复制路径”。
  2. 点击“编辑”修改内容并保存，关闭后重新打开核对内容与更新时间。
  3. 再次进入编辑并修改草稿（暂不保存），同时在服务端外部（或通过 Agent）修改同一记忆文件，随后在网页点击“保存”；出现冲突提示后，分别测试点击“重新加载”与关闭弹窗。
- **期望结果**：
  - 页内直接预览 Markdown 正文并可复制服务端路径，不再调用本机外部编辑器；保存后文件内容与列表更新时间刷新。
  - 外部改动导致版本（`updatedAt` + `contentHash`）不一致时拒绝覆盖（`PROJECT_MEMORY_FILE_CHANGED`），显示冲突提示且完整保留当前编辑草稿。
  - 存在未保存草稿时，点击“重新加载”或关闭弹窗均会弹出放弃修改确认框，确认后才丢弃草稿。
- **风险与边界**：
  - 仅允许读写已存在的项目记忆 Markdown 文件（单文件 5 MiB 上限），不支持新建文件或写入任意路径。
  - 版本校验与同目录临时文件 `rename` 之间仍存在极短的文件系统竞态窗口。

### (3) 技能详情与 `.zcodeignore` 打开服务端路径及网页文件操作

- **人测动作**：
  1. 在有活动项目/工作区的状态下，进入“设置 -> 技能”点击技能路径，或在已保存 `.zcodeignore` 的“设置 -> 工作区文件搜索”页点击定位按钮；在打开的右侧文件管理面板中展开目录、单击文件，并对文件打开右键菜单执行复制路径、另存为/下载。
  2. 切换到无活动项目（不在项目中且无活动工作区）状态，进入“设置 -> 技能”点击用户级技能路径，查看弹出的页内目录浏览弹窗，关闭弹窗后刷新页面检查顶栏/侧栏工作区标签。
- **期望结果**：
  - 有活动工作区时在页面右侧打开文件管理面板并定位到目标服务端目录；单击目录展开/收起，单击文件打开页内预览，右键支持复制绝对/相对路径及触发浏览器下载副本（≤50 MiB，提示已开始下载）。
  - 无活动工作区时打开技能路径会弹出页内 `DirectoryBrowser` 目录浏览 Dialog，关闭并刷新后不会把该技能目录建成多余的持久工作区或标签页。
- **风险与边界**：
  - `.zcodeignore` 尚未落盘（处于初始模板态）时定位按钮禁用，需先保存生成文件后才可定位。
  - 网页端仅浏览服务端目录、页内预览与下载副本，不支持调用访问者电脑本地应用直接打开服务端文件。

### (4) 从服务端目录添加插件市场源与风险确认

- **人测动作**：
  1. 进入插件市场打开“添加来源”弹窗，输入路径但先不勾选风险确认，尝试点击“添加”按钮或按回车。
  2. 点击“选择目录”，在弹窗内嵌的服务端目录浏览器中选定目录。
  3. 勾选风险确认后提交添加；关闭弹窗再次打开，检查风险确认复选框初始状态。
- **期望结果**：
  - 点击“选择目录”在弹窗内直接浏览服务端目录（复用 `PluginStorePage` 当前与添加操作同源的 Host 服务），选定后将服务端绝对路径填入输入框。
  - 未勾选风险确认或来源为空时，“添加”按钮禁用且按回车不会绕过校验（输入法候选词确认也不会误触提交）；关闭弹窗后风险确认自动重置；若添加失败则保留输入内容与错误提示以便修正重试。
- **风险与边界**：
  - 独立 Web 不支持将访问者电脑上的本地文件夹拖入弹窗解析路径；所选目录必须是当前目标 Host 可访问的有效插件源目录。

### (5) 设置页四类资源的作用域（Scope）“当前服务器”文案

- **人测动作**：
  1. 在独立 Web 打开设置页，依次查看插件（顶栏/列表共用 `PluginScopeMenu`）、技能、子代理、MCP 的作用域选择器与个性化指令说明文案。
- **期望结果**：
  - 独立 Web 下当前服务器承载的 `local` 设备 `user` 范围统一显示为“当前服务器”（触发器收敛为单一“当前服务器”标签，不重复拼接），远端（`remote`）设备分组仍显示其自身设备名与“用户”标签，项目范围显示为“当前项目”。
- **风险与边界**：
  - 仅更新独立 Web / 手机远控下当前服务器承载作用域的界面文案，不改变底层 `user` / `local` / `project` 配置读写归属，也不会将其他远端设备的用户范围误标为“当前服务器”。

### (6) 内置 `skill-creator` 默认加载与动态工作流资源（`dynamic-workflows`）随包就绪

- **人测动作**：
  1. 容器启动后，在设置页插件与技能列表中检查内置官方插件（含 `skill-creator`、`zcode-guide`、`visualize` 等 15 个插件）及内置技能是否正常列出。
  2. 核对 `skill-creator` 与 `dynamic-workflows`（`/workflow` 所需 `SKILL.md`、`patterns.md`、`examples.md`）是否直接由发行包内置路径（`agent/packages/*` 及运行时内置缓存）提供。
- **期望结果**：
  - `skill-creator` 默认随服务端加载，`dynamic-workflows` 内置技能包随镜像就绪，无需也不应使用外部同名插件或技能替代。
  - 部署验收只需通过界面列表或静态路径确认内置资源就绪，**不需要为验证专门发起付费模型请求**；实际使用中如需调用相关技能，由用户按需自行发起。
- **风险与边界**：
  - 打包阶段若缺少任一官方插件清单、必需种子文件、运行时 `dist/mcp/server.js` 或 `web/index.html`，构建会直接报错中止，不会产出缺资源的归档包。
